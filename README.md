#紧箍咒 · Causality Cage

> **AI 穷举 + 系统剪枝 = 可审计的因果推演**

给大模型套上的状态机与逻辑沙盒：**候选生成交给 AI，但否决权留在系统手里。**

大模型会流畅地说出一切听起来合理的话——它不会告诉你哪一句是胡说。
本项目换了个分工：**让 AI 负责穷举，让规则引擎负责否决。**

```bash
git clone <this-repo> && cd <this-repo>
python demo.py          # 零依赖、零联网、零 API Key
python tests/test_engine.py   # 引擎核心不变量测试
```

---

## 一、为什么需要它

直接问大模型「CPI 会上行还是下行」，你会得到一段车轱辘话：
语句通顺、术语正确、**没有任何一步可被检验**。你无法回答：
「它凭什么这么说？」「如果前提变了还成立吗？」

本项目把推演变成一棵**可审计的树**：

| | 裸问大模型 | 接入本项目 |
|---|---|---|
| 输出形态 | 一段流畅文本 | 一棵带剪枝记录的树 |
| 每一步依据 | 不可见 | **规则 id 可追溯**（如 `PRUNE-ABS-LPR1Y`）|
| 前提可换 | 否 | 是（换一个 `--signal` 重跑）|
| 被否决的路径 | 无记录 | **全部留痕，含否决依据** |
| 能否断言 | 不能 | 能，且知道断言的边界 |

**核心主张：系统不替 AI 编答案，但系统有权拒绝明显错误的答案。**

## 二、真实运行结果

以下数字全部来自本仓库代码的真实运行，**不是示意、不是手绘**。

一次真实推演（信号：`9月CPI PPI居民消费价格数据`，深度 4）：

| 指标 | 实测值 |
|---|---|
| 展开节点数 | **532** |
| 树深 | **4 层**（depth0=1 → depth1=9 → depth2=80 → depth3=442）|
| 剪枝规则命中 | `PRUNE-ABS-LPR1Y` **60** 次 · `PRUNE-ABS-LPR5Y` **60** 次 · `PRUNE-ABS-001` **59** 次 |

被剪掉的典型候选（真实规则原文）：

- **「LPR 1Y 上行」** → `PRUNE-ABS-LPR1Y`：LPR 自 2019 年报价改革以来**只降不升**，推上行方向不成立
- **「10Y 国债收益率上行」** → `PRUNE-ABS-001`：低通胀 + 政策非偏紧下推收益率上行 = 荒谬
- **「通胀担忧叙事」** → `PRUNE-NARR-001`：与世界状态（CPI≤1.5%）直接矛盾

注意最后一条：**AI 会主动生成「通胀担忧」这个叙事**（在别的语境下它完全合理），
是系统把它挡在了树外。这就是「否决权在系统」的具体形态。

`python demo.py` 的真实输出（节选）：

```
推演树（●=存活节点，✂=被剪掉的候选）
● [depth=0]
  ✂ [HARD_PRUNE] narrative:inflation_concern  ← PRUNE-NARR-001-DEMO
  ↳ narrative:cost_push [有据]
    ● [depth=1]
       ↳ narrative:demand_weak [有据]  <L3_visited>
...
剪枝汇总
存活节点: 53    被剪候选: 29
  ✂ HARD_PRUNE narrative:inflation_concern        依据规则: PRUNE-NARR-001-DEMO
```

`<L3_visited>` 不是 bug，是**状态塌缩检测**：走到同一个世界状态时停止展开，
避免把相同的未来重复叙述一百遍。绝大多数 LLM「深度推演」栽在这里——
它们不会承认自己绕圈了。

## 三、架构

```
        ┌──────────────────────────────────────────┐
        │  AI 层（可替换：任意大模型）             │
        │  职责：穷举候选、提出假设│
        │  权力：无否决权                │
        └────────────────┬─────────────────────────┘
                         │  generate(state, narrative_layer,
                         │           node_context, seen)
                         ▼
        ┌──────────────────────────────────────────┐
        │  系统层（不可替换：规则引擎）             │
        │  ├ hard_prune    硬剪枝（逻辑/物理/制度） │
        │  ├ constraints   约束层                   │
        │  ├ canon         规范登记表（别名归一）    │
        │  └ world_tree    状态演化 + L3 去重       │
        │  权力：最终否决                            │
        └────────────────┬─────────────────────────┘
                         ▼
                  可审计的推演树
```

**关键设计：`ai_candidate` 模块在未注入任何生成器时显式抛错，而不是静默返回空。**
系统宁可拒绝运行，也不伪造一个「看起来正常」的结果。
`tests/test_engine.py` 组1 就是在钉这条不变量。

## 四、开源了什么 / 没开源什么

### ✅ 开源（发动机）

| 文件 | 作用 |
|---|---|
| `tools/world_tree.py` | 树演化主体：状态推进、候选注入、L3 状态去重 |
| `tools/hard_prune.py` | 硬剪枝引擎：7 类约束的机器可判定规则 |
| `tools/ai_candidate.py` | 候选槽位契约（含「未注入即报错」的设计）|
| `tools/llm_generator.py` | 标准 LLM API 适配器（OpenAI 兼容，stdlib 零依赖）|
| `tools/canon.py` | 规范登记表：别名归一 + 范围外拒收 |
| `tools/test_engine.py` | 引擎核心不变量测试（零依赖）|

### ❌ 不开源（汽油配方）

| 文件 | 为什么不发 |
|---|---|
| `config/state_step_model.json` | **真实资产步长分位数校准**（CPI/M2/CN10Y 等按 p25/p50/p75 + 样本量标定，n 最大 2340）。长期积累的数据资产，不是代码。|
| `config/transmission_graph.json` | 生产传导图（含实例统计）|
| 完整的 `prune_rules.json` | 仓库内是**裁剪后的示范子集**（标注 `NOT PRODUCTION-CALIBRATED`）。生产规则库经过长期领域校准，未发布。|

**取舍是刻意的**：引擎能让所有人跑通、看清机制；
但「在你的领域里剪掉什么」这份知识，得自己长出来。
这也是这个项目真正的门槛所在——不是代码难写，是**规则要一条条跟现实对撞出来**。

## 五、谁该用它

- **复杂剧情游戏 / NPC 行为系统** — 让 NPC 的行为链有硬边界，
  杜绝「为了推动剧情突然降智」。剪枝规则就是你的世界观物理定律。
- **金融 / 供应链推演** — 防止模型产生「听起来很专业的幻觉」。
  每个方向都有规则 id 可查，每条被否决的路径都留痕。
- **规则引擎 / 约束求解研究者** — 研究如何把大模型锁在物理与逻辑边界内。
  7 类约束（荒谬/矛盾/物理/时窗/叙事/认知/伦理）是一套可直接复用的框架。

**不适合**：想要一句话答案的场景。这套系统给你的是**可审计的过程**，
如果你只需要结论，它显得笨重。

## 六、接上你自己的大模型

`tools/llm_generator.py` 是 OpenAI 兼容适配器，stdlib 实现（`urllib`），无额外依赖：

```bash
export LLM_BASE_URL="https://api.your-provider.com/v1"
export LLM_API_KEY="sk-..."
export LLM_MODEL="your-model"
```

然后照 `demo.py` 里的注入点替换离线桩即可——**系统侧的剪枝逻辑一行都不用改**。

想扩展剪枝规则，照 `config/prune_rules.json` 的 schema 写就行：

```json
{
  "id": "PRUNE-XXX-001",
  "category": "logical_contradiction",
  "ground": "theoretical",
  "description": "人类可读的否决理由（会出现在运行日志里）",
  "when": { "all_of": [{ "metric": "CPI", "op": "<=", "value": 1.5 }] },
  "forbid_direction": { "target": "CN10Y", "sign": "up" }
}
```

## 七、已知边界（诚实披露）

1. **`config/prune_rules.json` 是示范子集**（8 条规则）。
   它足以让引擎跑通、让 demo 复现，但**剪枝覆盖面远小于生产版本**。
2. **真实资产步长模型未开源**，因此本仓库无法给出「每一步的幅度」。
   树能告诉你「哪些路径可能」，**不能告诉你「会走多远」**。
3. **demo.py 用离线种子世界状态**（占位观测值，非真实行情）。
   真实数据支路需要 `pip install pandas akshare` 并联网。
   demo 的目的是演示**剪枝机制**，不是演示数据质量。
4. **叙事域是开放的**，接受任意叙事 id。这意味着规则质量直接决定剪枝质量——
   规则不全时，系统不会乱剪，但也不会拦下所有错误。**这是刻意的取舍：
   宁可漏剪，不可误剪。**
5. **`tools/feeds.py` 在开源包内是降级桩**：真实数据采集实现未随包发布。
   `use_real_feeds=True` 时会返回**空集 + `source_status` 明确标注 `not_bundled`**，
   而不是静默返回空让人误以为「源里没有东西」。离线运行（`demo.py` / tests）不受影响。
6. **`src/` 目录**只包含规则与存储层（供引擎引用），**不含语料采集器**
   （`collect/`、`pipeline.py` 未发布：联网且依赖 pyarrow，非本项目核心）。

## 八、开发过程中真实踩过的坑

这些是引擎里带注释的"疤"，也是 `tests/test_engine.py` 逐条钉住的不变量：

| 坑 | 症状 | 修法 |
|---|---|---|
| 顶层 `import pandas` | fresh clone 后引擎直接 ImportError 起不来（明明纯逻辑推演根本不需要 pandas）| 改为惰性代理，只在真实行情支路才 import |
| 静默空结果 | 生成器未注入时返回空列表，上层看起来"正常跑完了"| 显式抛错，宁可拒绝运行也不伪造结果 |
| 状态塌缩 | 不同分支抵达同一世界状态后重复叙述| L3 visited 检测 + `_state_key` 含叙事集（否则 no-op 归因恒真）|
| 窗口口径误杀 | `chain_days` 拍脑袋给 30~180 天，全被 `WINDOW_FIT` 剪光| 用真实 `NARRATIVE_CHAIN_DAYS`（快通道 2 天 / 慢通道 10 天）|
| 虚假"桥接"披露 | 把路径上所有修饰叙事都算成"跨越"| `_longest_run` 只记真正桥接的节点 |
